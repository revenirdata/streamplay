Scenario suite
Select saved scenarios and run them sequentially through their configured adapters. Each case uses the same runner as the event editor. No expectations means OBSERVED, not PASS. Source and infrastructure regressions remain separate adapter checks.




Code-first: npm run run:suite -- streamplay-suite.json. Change application code, rebuild/restart it as needed, then rerun. The suite does not hot-reload your application.






01 Prepare events







Build a device event sequence

Generate editable JSON for up to 20 identities. Emit numeric values in named phases, or send nothing during a silence phase. This generates inputs; your application defines the behavior.






Uses the first input event as the template. For a rate in units/minute, a phase can use targetQuantity instead of durationMs. Maximum: 1,000 events and 120 seconds. Zero-valued events and silence are different.








One JSON value per non-empty line. Up to 1,000 events and 512 KB; invalid lines leave your current events unchanged.


Expected output optional
Exact JSON records, ignoring record order and object key order. Duplicate counts matter. Checked over the full observation window.


Expected output by phase optional
For a generated named sequence, assert when records are observed: [{"phase":"below","expected":[]}, ...]. The phase changes when its first event is dispatched. This is an observation-time check, not event-time attribution or proof of causality.


Timing & matching
Empty means full JSON matching. Selected fields affect assertions only; raw records remain unchanged. Missing fields fail the assertion. Planned timeline mode catches up overdue events; it does not discard them or guarantee real-time delivery.
